# cognia-diagnostic-server

Diagnostic report intake and crash symbolication service for Cognia. It accepts
consented, resumable diagnostic uploads, scans and symbolicates them, groups
them into incidents, and serves the triage API. Implements
[ADR-0102](../../docs/adr/en/0102-unified-observability-crash-diagnostics.md)
and
[ADR-0135](../../docs/adr/en/0135-diagnostic-service-completion.md),
both copied from cognia-next.

The caller is the Cognia app. Its submit path lives in cognia-next:
[`crates/cognia-observability/src/diagnostic_submit.rs`](https://github.com/MaxQian888/cognia-next/blob/dev/crates/cognia-observability/src/diagnostic_submit.rs)
on the desktop, and
[`lib/diagnostic-service/`](https://github.com/MaxQian888/cognia-next/tree/dev/lib/diagnostic-service)
for the frontend and mobile clients.

A single Rust binary (axum) backed by Postgres and an object store. It has its
own `Cargo.lock` and ships as its own container.

## Architecture

```
src/main.rs        bootstrap: config, Postgres pool, migrations, workers, graceful shutdown
src/config.rs      every environment variable (see Configuration)
src/api.rs         router and handlers, intake kill switch
src/auth.rs        HMAC-signed grants, OIDC (RS256) and Ed25519 installation proofs
src/db.rs          Postgres repository; every query runs in a tenant transaction
src/storage.rs     artifact store: S3-compatible or local directory
src/crypto.rs      per-tenant envelope encryption of every stored artifact
src/kms.rs         AWS KMS client (GenerateDataKey / Decrypt, SigV4-signed)
src/privacy.rs     privacy gate: credential rejection, email/bearer/path redaction
src/worker.rs      processing worker: scan, symbolicate, group
src/processing.rs  minidump-stackwalk runner, frame extraction, retry policy
src/retention.rs   retention worker and default retention policy
src/alert.rs       alert delivery worker (webhook, SMTP, OTel log signal)
```

- **API.** Clients exchange an identity for a short-lived grant (15 minutes),
  then create an incident, upload parts, and complete the upload. Grants carry
  a tenant, a project and a role: `uploader`, `viewer`, `triager`, `admin`.
- **Processing worker.** Claims due incidents per tenant, verifies each part's
  SHA-256, and runs the privacy gate. A part that contains a credential (private
  key, AWS key, provider secret, JWT) is deleted and the incident fails. A
  minidump goes through `minidump-stackwalk`, with the project's uploaded
  Breakpad symbols when there are any. Other parts yield frames from structured
  events. The result is fingerprinted (`fingerprint-v1`) into an incident group.
- **Storage.** Artifacts go to S3 (`S3_ENDPOINT`) or a local directory
  (`OBJECT_STORE_LOCAL_DIR`).
- **KMS envelope keys.** Each tenant has a data key generated by KMS and stored
  wrapped in `tenant_keys`. Artifacts are encrypted with AES-256-GCM under the
  tenant's active key version. Admins can rotate the key or crypto-shred the
  tenant.
- **Retention.** Accepted incidents get retention jobs. Defaults: minidumps 14
  days, attachments 30, metadata 90, symbols 180. Tenants can override them
  (`retentionOverrides`, at most 3650 days). Failed jobs retry with backoff.
- **Alerts.** A regression in a resolved group (`new_regression`) and missing
  symbols (`missing_symbols`) enqueue one delivery per transport: webhook,
  SMTP, and an OTel log signal. Webhooks carry an `idempotency-key` header and,
  with `ALERT_WEBHOOK_SECRET` set, an `x-cognia-signature: sha256=…` HMAC. A
  transport that is not configured fails permanently; others retry up to 10
  times.
- **Triage.** The console surface: list and filter groups and incidents, set a
  group's status (`open`, `suppressed`, `resolved`), read the audit trail, and
  download raw artifacts. Triage edits and artifact reads are audited with the
  OIDC subject as the actor.

Each worker runs inside the serving process and can be switched off on its own.

## HTTP API

The contract is [`openapi.yaml`](openapi.yaml). The server also serves it at
`GET /openapi.yaml`.

| Group          | Routes                                                                                                                                                                              | Minimum role                     |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------- |
| Health         | `GET /health/live`, `GET /health/ready` (checks Postgres), `GET /openapi.yaml`                                                                                                      | none                             |
| Grant exchange | `POST /v1/grants/oidc`, `POST /v1/grants/anonymous`                                                                                                                                 | none                             |
| Intake         | `POST /v1/incidents`, `GET /v1/incidents/{id}/parts`, `PUT /v1/incidents/{id}/parts/{part}`, `POST /v1/incidents/{id}/complete`, `POST /v1/incidents/{id}/cancel`                   | uploader                         |
| Incident       | `GET` / `DELETE /v1/incidents/{id}`, `POST /v1/incidents/{id}/withdraw`                                                                                                             | uploader (own installation)      |
| Triage         | `GET /v1/incidents`, `GET /v1/incidents/{id}/audit`, `GET /v1/incidents/{id}/artifacts`, `GET /v1/incidents/{id}/artifacts/{part}`, `GET /v1/groups`, `GET`/`PATCH /v1/groups/{id}` | viewer; triager to edit/download |
| Admin          | `GET`/`PATCH /v1/admin/tenant`, `GET /v1/admin/symbols`, `PUT /v1/admin/symbols/{buildId}/{platform}`, `POST`/`DELETE /v1/admin/tenant-key`                                         | admin                            |

Grants are sent as `Authorization: Bearer <grant>`. `POST /v1/grants/oidc`
takes an RS256 session token from the configured issuer; its `tenant_id`,
`project_id` and optional `role` claims become the grant (role defaults to
`uploader`). `POST /v1/grants/anonymous` takes an Ed25519 installation proof
with a single-use nonce and a timestamp within 5 minutes, and always yields an
`uploader` grant. Crypto-shred (`DELETE /v1/admin/tenant-key`) also requires an
`x-confirm-crypto-shred` header equal to the tenant id.

**Intake kill switch.** With `DIAGNOSTIC_INGEST_ENABLED=false` every intake
route answers `503 ingest_disabled`. Grant exchange, incident read, withdraw,
delete, triage and admin stay mounted, so deletion requests can still be
served.

**API changes land here first.** cognia-next keeps a byte-identical copy of
`openapi.yaml` at `protocol/cognia-services/diagnostic-openapi.yaml`, and its
`scripts/ci/check-cognia-services.mjs` compares the copy against the pinned
revision of this repository. Change the contract here, then copy it into
cognia-next together with a pin bump.

## Configuration

All configuration is environment variables. The binary takes no CLI flags or
subcommands.

| Variable                             | Default                                         | Meaning                                                                     |
| ------------------------------------ | ----------------------------------------------- | --------------------------------------------------------------------------- |
| `DIAGNOSTIC_BIND`                    | `0.0.0.0:8080`                                  | Listen address                                                              |
| `DATABASE_URL`                       | **required**                                    | Postgres connection string                                                  |
| `DATABASE_MAX_CONNECTIONS`           | `20`                                            | Pool size                                                                   |
| `DIAGNOSTIC_RUN_MIGRATIONS`          | `true`                                          | Apply migrations at startup. Set `false` when a separate job owns DDL       |
| `DIAGNOSTIC_MIGRATE_ONLY`            | `false`                                         | Apply migrations and exit. Requires `DIAGNOSTIC_RUN_MIGRATIONS=true`        |
| `DIAGNOSTIC_INGEST_ENABLED`          | `true`                                          | Intake kill switch (see above)                                              |
| `S3_ENDPOINT`                        | unset                                           | S3-compatible endpoint. One of this or `OBJECT_STORE_LOCAL_DIR` is required |
| `OBJECT_STORE_LOCAL_DIR`             | unset                                           | Store artifacts in a local directory instead of S3 (wins when both are set) |
| `S3_BUCKET`                          | `cognia-diagnostics`                            | Bucket name                                                                 |
| `S3_REGION`                          | `us-east-1`                                     | Bucket region                                                               |
| `S3_ACCESS_KEY` / `S3_SECRET_KEY`    | unset                                           | Object store credentials                                                    |
| `GRANT_SIGNING_KEY`                  | **required**                                    | HMAC key for grants, at least 32 bytes                                      |
| `OIDC_ISSUER`                        | **required**                                    | Expected `iss` of session tokens                                            |
| `OIDC_AUDIENCE`                      | **required**                                    | Expected `aud` of session tokens                                            |
| `OIDC_PUBLIC_KEY_PEM`                | **required**                                    | RSA public key (PEM). Literal `\n` sequences are accepted                   |
| `KMS_KEY_ID`                         | **required**                                    | KMS key that wraps tenant data keys                                         |
| `KMS_ACCESS_KEY_ID`                  | **required**                                    | KMS credentials                                                             |
| `KMS_SECRET_ACCESS_KEY`              | **required**                                    | KMS credentials                                                             |
| `KMS_SESSION_TOKEN`                  | unset                                           | Optional temporary-credential token                                         |
| `KMS_REGION`                         | `us-east-1`                                     | KMS region                                                                  |
| `KMS_ENDPOINT`                       | `https://kms.<KMS_REGION>.amazonaws.com/`       | KMS endpoint, no query string                                               |
| `KMS_TIMEOUT_SECONDS`                | `15`                                            | KMS request timeout                                                         |
| `PROCESSING_ENABLED`                 | `true`                                          | Run the processing worker                                                   |
| `PROCESSING_INTERVAL_MS`             | `1000`                                          | Poll interval                                                               |
| `PROCESSING_BATCH_SIZE`              | `32`                                            | Incidents per round, 1 to 1000                                              |
| `PROCESSING_TEMP_DIR`                | `<system temp>/cognia-diagnostic-processing`    | Scratch directory for stackwalk runs                                        |
| `MINIDUMP_STACKWALK_PATH`            | `/usr/local/bin/minidump-stackwalk`             | Path to `minidump-stackwalk`                                                |
| `MINIDUMP_STACKWALK_TIMEOUT_SECONDS` | `120`                                           | Per-run timeout                                                             |
| `RETENTION_ENABLED`                  | `true`                                          | Run the retention worker                                                    |
| `RETENTION_INTERVAL_MS`              | `5000`                                          | Poll interval                                                               |
| `RETENTION_BATCH_SIZE`               | `32`                                            | Jobs per round, 1 to 1000                                                   |
| `ALERT_ENABLED`                      | `true`                                          | Run the alert worker                                                        |
| `ALERT_INTERVAL_MS`                  | `1000`                                          | Poll interval                                                               |
| `ALERT_BATCH_SIZE`                   | `32`                                            | Deliveries per round, 1 to 1000                                             |
| `ALERT_TIMEOUT_SECONDS`              | `15`                                            | Webhook request timeout                                                     |
| `ALERT_WEBHOOK_URL`                  | unset                                           | Webhook target                                                              |
| `ALERT_WEBHOOK_SECRET`               | unset                                           | HMAC secret for `x-cognia-signature`                                        |
| `ALERT_SMTP_URL`                     | unset                                           | SMTP transport URL                                                          |
| `ALERT_SMTP_FROM` / `ALERT_SMTP_TO`  | unset                                           | Sender and recipient for SMTP alerts                                        |
| `RUST_LOG`                           | `cognia_diagnostic_server=info,tower_http=info` | Log filter. Logs are JSON                                                   |

Booleans accept `1`/`true`/`yes`/`on` and `0`/`false`/`no`/`off`. Anything else
fails startup.

## Database

Postgres. Migrations are sqlx migrations in [`migrations/`](migrations/),
embedded in the binary. sqlx checksums every applied migration, so **never edit
an applied migration**. Add a new numbered file instead.

Every tenant table has row-level security forced on, keyed by
`current_setting('app.tenant_id')`. The repository sets it per transaction with
`SELECT set_config('app.tenant_id', $1, true)`. cognia-next's
`crates/cognia-tenant-auth` describes the same contract and has an ignored test
that reads this server's `src/db.rs` and `migrations/0001_diagnostics.sql` from
a checkout named by `COGNIA_SERVICES_ROOT`. Coordinate any change to that
statement or the RLS predicate with cognia-next.

## Local development

The Rust toolchain is pinned by the repository root `rust-toolchain.toml`.

```bash
cd services/diagnostic-server
cargo test --locked
```

The unit tests need no Postgres, object store or KMS.

To run the full stack (Postgres, MinIO built from pinned sources, and a
LocalStack-compatible KMS stub), use the compose project in `deploy/`:

```bash
cd services/diagnostic-server/deploy
docker compose up -d --wait diagnostic-service
```

Bring-up order is `postgres` → `migrate` (runs the image with
`DIAGNOSTIC_MIGRATE_ONLY=true`, then exits) → `seed` → `diagnostic-service`
(with `DIAGNOSTIC_RUN_MIGRATIONS=false`). The KMS stub creates
`alias/cognia-diagnostics` from `deploy/floci-init/`. The seed
(`deploy/seed/10-development-tenant.sql`) adds a development tenant
`00000000-0000-4000-8000-000000000001` with one project
`00000000-0000-4000-8000-000000000002`. The service listens on port 18080:

```bash
curl -i http://127.0.0.1:18080/health/live    # 204
curl -i http://127.0.0.1:18080/health/ready   # 204
curl -s http://127.0.0.1:18080/openapi.yaml
```

Try the intake kill switch:

```bash
DIAGNOSTIC_INGEST_ENABLED=false docker compose up -d --wait --force-recreate diagnostic-service
curl -s -o /dev/null -w '%{http_code}\n' -X POST http://127.0.0.1:18080/v1/incidents \
  -H 'content-type: application/json' -d '{}'   # 503
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:18080/v1/groups   # 400: still mounted, no grant
```

Tear down, including volumes:

```bash
docker compose down -v
```

The compose defaults (passwords, `GRANT_SIGNING_KEY`, the OIDC key) are for
development only.

## Deployment

`.github/workflows/images.yml` publishes `ghcr.io/cognia-labs/cognia-diagnostics`
from this directory's `Dockerfile`. The image bundles `minidump-stackwalk`
0.26.1 and runs as uid 10001.

- Pushes to `main`: `edge` and `sha-<short sha>`.
- `v*` tags: `<version>`, `<major>.<minor>` and `latest`.
- Pull requests build without pushing.

For Kubernetes, use the Helm chart in
[`deploy/helm/cognia-diagnostics/`](deploy/helm/cognia-diagnostics/README.md).
It runs migrations in a pre-install/pre-upgrade Job and keeps the serving pods
on a role with no DDL grant.

## Tests and CI

`.github/workflows/diagnostic-server.yml` runs on changes to this directory, to
`rust-toolchain.toml`, or to the workflow itself:

- **Rust tests:** `cargo test --locked`.
- **Diagnostics stack:** `node --test deploy/minio-pin.test.mjs` (MinIO is
  built from pinned official sources), then the compose bring-up above. It
  checks that `migrate` and `seed` exited 0, that the development tenant's
  project exists, that health and OpenAPI answer, and that with the kill switch
  off intake answers 503 while grant exchange, triage and liveness stay up. It
  tears down with `docker compose down -v`.
